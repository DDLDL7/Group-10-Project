Running GridCare‑Lite

A desktop tool for logging outages, assigning work orders, and tracking repairs through to resolution — one screen per role, so nobody sees more than their job requires.

01 Installation

Run this from inside the gridcare-lite/ folder.

terminal
pip install -r requirements.txt
python main.py

The first launch creates db/gridcare.db, seeds four demo accounts, and imports substation and line reference data from ../grid-analysis/data/.

02 Logging in

Enter your username and password and select Log In. An incorrect username or password shows one plain error without hinting which part was wrong. Once you're in, the dashboard shows only the actions your role is permitted to perform — nothing is hidden behind a setting you have to know to look for.

03 By role

Each role sees a different dashboard. Here's what each one can do.

Engineer

Reports faults as they happen

  1. Report New Outage — pick the affected substation, describe the fault, choose a severity (Low / Medium / High / Critical), then submit. The outage opens with status Open.
  2. View Outages — a table of every outage, filterable by region and status, refreshed on demand.
Administrator

Assigns the work and watches the numbers

  1. View Outages — the same outage table.
  2. Assign Work Order — pick an open outage, pick a technician, set a scheduled date (YYYY-MM-DD), and confirm. The outage moves to In Progress automatically.
  3. Reports — total, open, and resolved outage counts, average resolution time in hours, and a breakdown by region.
Technician

Works the queue that's actually assigned to them

My Work Orders lists only the work orders assigned to you. Select a row, then:

  • Mark In Progress — records that repair work has started.
  • Mark Completed — completes the work order and resolves the linked outage, stamping the resolution time.

You cannot update a work order assigned to someone else, even by selecting its row — the check happens independently of what's shown on screen.

Customer service

Connects a complaint to a known outage

  1. View Outages — check whether a caller's report matches something already logged.
  2. Log Customer Complaint — enter the customer's name, optionally the outage ID if known, and the complaint text, then save.

04 If something goes wrong

Nothing here should ever crash the app — every one of these fails with a plain message instead.

BlockedSubmitting with a required field empty shows an error and saves nothing.
BlockedA scheduled date that isn't YYYY-MM-DD is rejected before it reaches the database.
BlockedA non-existent substation or outage ID is rejected with a message, not a crash.
EnforcedAn action your role doesn't permit is blocked in the underlying logic — not just by hiding the button.

05 Logging out

Select Log Out on your dashboard at any time to return to the login screen. Any open outage-dashboard, reports, or technician-orders windows close automatically.
